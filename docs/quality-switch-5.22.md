# 5.22 音质切换稳定性

沿用包名、正式签名、原生播放器和现有插件协议。先在独立且不启动的原生播放器中准备新档位，准备并对齐进度后再移交当前播放。不会以请求档位冒充音源实际音质。

来源授权、HTTP、音频准备或解码失败时，原播放器、播放进度和暂停状态继续保留，音质偏好恢复到当前实际档位，并显示原始来源错误和可用的登录或重试入口。准备过程中暂停、拖动、音量变化沿用当前服务状态。快速选择只采用最后一个请求；重新选择当前档位取消待处理请求；切歌和停止取消旧请求，避免旧回调重新启动歌曲。同曲已上报状态跨多次暂停切换保留，避免重复 played。

缓存对当前音频和待切换音频分别保留占用，交接或取消时释放。来源字段、账号、请求头与原有音量均衡仍沿用既有实现。解码临时文件随取消或交接转移所有权。

全屏歌词页顶部新增音质按钮，可以直接使用现有三档选择。原有十种动效保持不变。

Android 官方媒体状态与异步定位依据：https://developer.android.com/reference/android/media/MediaPlayer 。交接时先以静音确认新播放器能够启动，再释放旧播放器并应用当前音量；不会同时输出两路音频。启动异常仍保留旧播放器。

新增原生回归覆盖授权拒绝、HTTP 403、解码器拒绝、准备时暂停和拖动、快速选择、取消、切歌和停止，并检查实际播放器身份、时钟、偏好和来源上报。已有 ALAC 16/24 位及全套歌词、缓存、后台、登录、插件回归继续运行。

完整云端结果、覆盖升级与交付文件校验待构建完成后记录。实体手机和真实会员权限未实测。

## 原生网络与登录会话

新的 HTTP 音频回归提前初始化了系统 MediaPlayer 网络层，暴露出 java.net 的全局自动 Cookie 容器会重用其他插件响应 Cookie，并覆盖 B 站候选登录请求的显式 Cookie。原生来源会话一直由各插件显式保存和附带，WebView 登录使用独立的 android.webkit.CookieManager。现在在应用启动时为 java.net 安装不自动存取 Cookie 的处理器，保留插件显式请求头和 Set-Cookie 返回值，阻止媒体初始化创建跨来源的隐式容器。没有在请求间临时切换全局处理器。

原生回归在媒体初始化后检查响应 Cookie 不自动复用、显式 Cookie 原样送达、不同插件实例不继承会话；B 站候选校验与喜马拉雅、QQ 网页登录回归继续保留。Android 实现依据：https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android13-release/media/java/android/media/MediaHTTPService.java 。

## 网页二维码首次加载

旧版 WebView 的可视帧回调可能先于首次 onPageStarted 到达，导致已经显示二维码时点击放大，却被迟到的首次回调当成旧页面取消。现在在发起首次加载时计入页面身份，首次同地址的加载回调不重复更换身份；后续刷新、跳转、关闭和旧 WebView 回调仍使旧捕获失效。继续从真实可见像素解码，不读取网页隐藏凭据。
