# 5.41 音频分析后续审计

基线为已交付并合入main的142cab23767f4f1b38f27d40073797c8d3bab3cd，5.40.0 / 90。开始修改前工作区干净，十主题和播放器核心继续沿用。

## 确认的问题

1. ThemeSeekBar 的实际波形使用 postInvalidateOnAnimation 连续重绘，没有接入已提供的低性能及减少动态效果参数。
2. PlayerAudioCaptureService 初始化或采集中发生错误时，onDestroy 会将具体原因改写为音频分析已关闭，用户无法区分失败与主动停止。
3. 原采集循环不识别拖动、换歌和重新创建播放器的边界。快速暂停再恢复可能使旧read返回错误时，当前wanted已经重新为true，从而错误停止整个分析服务；旧FFT回调也没有过期检查。

## 本轮改动

波形进度条接入当前主题绘制预算。音频分析使用递增版本区分有效PCM，暂停、静音、显示状态变化及播放会话重建会清除旧数据；读循环在边界后重新采样，过期回调不能重新写入显示数据。PlaybackService仅发布既有播放状态和失效通知，不改变音频解码、输出、队列、Cookie或音质选择逻辑。

初始化及真实采集错误保留具体说明，主动停止仍显示正常关闭。结束旧采集线程时不覆盖已经关闭的会话。保留同UID的真实双声道系统捕获和权限流程，没有生成替代频谱。

新增原生测试使用40秒双声道音源，前段440/880Hz、后段1320/1760Hz，下一首660/990Hz。检查实际系统授权失败后的错误保留与恢复、原生seek后的频率变化、旧PCM回调拒绝、12次快速暂停/恢复/静音、下一首切换、关闭采集不停止音乐。另以实际有PCM数据的独立原生波形窗口比较正常与低性能模式的重绘次数，并确认暂停后重绘停止。该计数仅为模拟器调度验证，不作为手机帧率、温度或耗电数据。

沿用全部既有Node、Android和64来源审计，并新增从刚交付的5.40.0覆盖升级。正式签名和包名保持不变，版本为5.41.0 / 91。
