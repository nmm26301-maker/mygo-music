# 5.17 QQ 官网登录与摄像头扫码限制

本轮依据用户最新截图修正判断：该次 QQ 授权明确不支持图片识别或长按扫描，要求摄像头扫一扫。刷新二维码、提高图片清晰度和保存到相册都不能取消这项平台要求。5.16 的相册方案不能完成这类授权，不能称已验证真实 QQ 登录成功。

## 本轮实现

对 Amamiya23/mygo-music-qq-plugin 已核验的原版打包源码增加内存适配，保留安装文件及原账号数据。默认打开 QQ 音乐官网 https://y.qq.com/portal/player.html ，使用官网实际提供的账号密码等登录方式。窗口可竖屏和缩放，结束或取消后恢复播放器横屏。

普通 QQ 网页 Cookie、昵称或二维码保存都不算音乐登录成功。必须拿到账号标识和音乐凭据，再调用原插件账号接口校验，校验成功后才保存到原来源私有存储。使用网页凭据时，接口采用网页请求上下文和 CgiGetVkey 取流；原生扫码凭据仍使用原插件接口，凭据会传给原有搜索、账号和取流流程。

QQ 摄像头授权码不再显示本机相册可以完成授权的说明，也不再自动打开 QQ 引导选图。明确选择摄像头扫码时，需要另一块屏幕展示；已核验来源提供切换官网网页登录入口。其他可相册识别的平台流程保留。

官网窗口不注入账号密码表单、不读取密码、不伪造摄像头扫描来源、不冒用 Android 应用签名或 SDK 回调。平台的密码、验证码、二次验证和扫码要求仍由本人在官方页面完成。如果官网只给出摄像头扫码，本机单手机相册路径仍然不可用；本版本不承诺消除平台验证。

## 登录方式

默认及原来存为 qq 的方式改为官网网页登录。来源设置还可明确选择官网微信账号登录、QQ 摄像头扫码或原插件微信扫码。账号类型必须与所选方式一致。微信扫码是否允许相册，同样取决于实际平台要求，不能承诺统一可用。

页面若只取得普通网页账号态，窗口继续等待音乐凭据，不会虚报成功。用户取消或账号校验失败不会覆盖已有来源凭据，临时网站 Cookie 在结束后清理。旧会话写入拦截继续保留。

- egoist/mygo-music，AGPL-3.0，GitHub 维护至 2026-11-11：沿用 host.webSignIn 的独立网站登录与返回 Cookie 设计，继续使用本项目已有 Android WebView 实现，没有新建后端或引入 Electron。
- Amamiya23/mygo-music-qq-plugin，AGPL-3.0，当前提交 378b5555172fbf9e71028aa2c3ab9c7f17f24b8a，2026-11-10 更新：保留原插件的候选凭据校验、账号保存和取流，适配固定源码指纹 cf6fdcb57ac32da865e6cc4d6d34bfecdfa2970e33da8659dba5a40de384f8bc。未知版本不擅自改写。
- 其他桌面播放器有内嵌官网捕获音乐 Cookie 的设计，但桌面验证不能代替 Android 验证。未确认许可证的实现没有复制进项目。
- 官方页面匿名读取已返回 HTTP 200 且存在播放器登录入口；这不能证明用户账号一定能免扫码登录。

## 验证

本地检查覆盖：拒绝普通 QQ Cookie、别名处理、账号规范化、明确 QQ/微信类型、仅官网入口、不提供相册授权、候选校验先于保存、取消和非法输入。

新增 Android QQWebsiteChecks 使用原版固定源码，验证普通网页态继续等待，音乐凭据经原账号接口确认后存储，原版取流取得授权并推进原生播放时钟，账号校验失败和取消保留原凭据，临时 Cookie 隔离，以及网页登录竖屏和回到横屏。受控网站与账号不是用户真实 QQ 账号，也不能证明平台密码登录对所有账号放行。

本轮还须通过既有酷狗及概念版、歌词、背景播放、ALAC、HLS 缓存、插件与市场回归，验证旧签名覆盖升级。最终构建与文件校验记录在发布时补充。
