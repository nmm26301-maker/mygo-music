# 5.16 手机扫码与酷狗取流修复

从 5.15.0 继续，没有重新初始化。包名、签名保持不变，内部版本号 66。

## 已确认的代码问题

用户截图中的酷狗提示来自 fcmfcm1999/mygo-music-kugou 的 stream：它仅请求一次播放地址，固定专辑和专辑音频标识为 0，设备 dfid 固定为减号；没有地址时统一显示版权或账号权限限制。这个判断没有核验会员，不能据此认定用户没有会员。

bitbyte404/mygo-music-kugou-lite 已有设备注册和账号保存，但取流仍只遍历原 /v5/url，没有补齐现有账号校验、歌曲授权和 /tracker/v5/url 链路。对比当前 MakcRe/KuGouMusicApi 的 user_verify、song_auth、song_url_auth 和 song_url，新增流程保留本来源的 token、userid、mid、dfid、3116 平台、专辑及专辑音频标识。不同来源和不同平台的账号凭据没有互相拼接。

旧的原生登录窗口只能保存现有码，没有重新申请二维码的入口。保存的图片本身不会随登录票据失效而更新。对 QQ 既有请求进行一次匿名核查，新生成二维码的服务端状态为 66，即等待扫码；没有真实 QQ 账号参与确认，因此不能把截图归结为某一个已实测根因。

## 修复实现

- 登录窗口提供刷新二维码，刷新时创建新插件运行时并重新调用 signIn。保存与打开扫码 App 之前先取得新码，取消旧等待；旧结果不会覆盖新会话，已关闭会话的迟到原生存储写入也会被拒绝。
- 显示二维码生成后经过的时间，提示从相册选最新图片；过期后返回播放器刷新。保留同机保存、打开账号 App、相册识别和等待服务端确认。
- 插件网络连接不使用 URLConnection 缓存；网站登录原有无缓存设置保留。
- 对已核验源码指纹的酷狗与概念版添加内存适配，保留原安装文件、许可证和账号数据；未知源码版本不擅自改写。
- 酷狗会员取流先使用完整设备和歌曲参数请求正常地址，必要时执行当前账号验证、歌曲授权、授权取流。没有登录凭据、凭据失效、设备验证及空地址分别提示。
- 不把试听、未知或加密音频误记为完整可播放音频，不解密 DRM，不伪造会员。
- fcmfcm1999 原清单未包含设备注册域名，增加设备注册前的单独许可，允许或拒绝都会被执行，可在来源设置中撤回。没有静默扩大原插件网络权限。

## 安装后

直接覆盖安装。已有凭据保留，可以先重试播放。二维码登录使用刷新并保存入口，只扫描最新图片，确认后返回播放器。若当前来源未登录，应在播放器内登录对应来源，官方 App 中已有会员不会自动给此插件建立会话。

平台明确要求设备验证时会显示实际错误码；这类响应不等于没有会员。真实会员账号、网络和平台风险控制仍需在用户设备验证，不能用模拟结果代替。
