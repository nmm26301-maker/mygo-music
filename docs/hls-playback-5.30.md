# v5.30.0 分段音频播放修复

版本代码 80。沿用 com.mygo.music 包名和正式签名。

## 本轮处理

此前 HLS 在线播放直接交给系统播放器，只有完整离线缓存会经过 Java 请求处理。根清单取得音频地址后，子清单、音频片段、密钥和跨域跳转的请求头处理并不一致，可能出现已取得地址却无法准备音频的问题。

本版为在线 HLS 接入逐资源的本机传输。使用原有的来源请求头规则与手动重定向处理，每个资源单独匹配来源；显式音频凭据仅用于原始同源资源。保留主清单、分段、字节范围和普通 AES-128 密钥请求。在线允许直播清单，离线缓存继续要求完整结束的歌曲，不将直播保存成完整离线音频。受 DRM 保护或当前不支持的清单仍明确报错。

当系统明确拒绝分段音频格式，或分段读取没有网络错误但原生准备持续超时时，完整歌曲会经现有固定版本解码器生成兼容 FLAC 后再播放，保留来源请求头、进度和取消控制；不对网络或认证错误尝试格式回退，直播与受保护清单不进入完整文件转换。转换继续沿用 128 MB 输出和 3 分钟处理上限，实际源音质不会因此提高。

音质替换使用同一传输与解码回退逻辑。新音质准备时继续旧音频；成功后将传输交给播放服务持有，失败或取消时清理新传输。暂停、跳转、停止及后续歌曲的清理规则继续由原播放服务负责。传输关闭在后台完成，避免界面线程等待网络断开。

本机原生音频准备增加 30 秒上限。普通音频超时显示可重试的错误，符合条件的分段音频进入完整歌曲解码回退；转换失败仍显示原错误，不一直停留在准备状态；旧歌曲的超时回调不能中断后来开始的歌曲。解码和平台授权仍保留各自原有检查。

自动缓存保留原始来源 URL，而非暂时的本机传输地址。市场检查使用相同的生产 HLS 传输，并记录所用传输与可获得的分段错误详情，避免裸系统播放器的结果被误当作整个应用链路的结果。安装、搜索、HTTP 音频和原生准备仍为不同检查阶段。

## 验证设计

新增 Android 原生检查使用真实 HTTP 清单与音频文件，覆盖主清单、直播、普通 AES、系统不支持的 Opus 分段音频及音质替换回退、认证片段与密钥、直接跨域片段和跨域重定向、音质交接后的播放时钟与暂停进度、失败替换保护、原地址离线缓存、准备超时与过期回调、停止清理。保留已有完整回归与原签名覆盖安装检查，最终结果见交付说明。

## 尚未完成

本轮不提高兼容协议版本，也未完成 YouTube Music 新版插件移植。已查看其官方仓库的 plugin.json、README 和 index.js：新版要求 0.1.31，使用安全凭据存储、代理和桌面 ffmpeg/yt-dlp 辅助程序，需继续移植与验证这些实际能力。参考：https://github.com/maxbeau/mygo-music-youtube-music 。

第三方真实登录、会员授权、地区限制、接口状态、自建服务器和远程设备仍须满足对应来源条件。本轮分段播放修复不能据此宣称所有来源都能使用。
